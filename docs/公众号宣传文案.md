# 公众号文章：别再手写书源了！AI 自动生成香色闺阁书源，四层验证保证可用

> 适用：香色闺阁（StandarReader 2.56.1）用户 · 公众号「好用的软件站」原创

## 你是不是还在这样找书源？

- 看到别人发的 `.xbs` 书源文件，导入后搜索没结果、正文空白、一保存就闪退
- 想给自己常看的网站写个书源，一看那串 `@js:` 规则就头大
- 网上的书源要么过期、要么带广告、要么不兼容新版香色闺阁

**书源的本质**：告诉 App「去哪个网址、抓哪个标签、怎么拼下一页」。听起来简单，但每个网站的页面结构都不一样，手写一个能用的书源，快则半小时，遇到反爬/分页/GBK 编码，一下午就没了。

## 我们把「写书源」变成了流水线

基于 **AI + Skill 工作流**，我们把整个流程拆成了可验证的四道关卡：

```
网站页面 → AI 写规则 → ① 格式校验 → ② 编辑器兼容检查
        → ③ 真实页面解析测试 → ④ 真实网络四步链 → 打包 .xbs → 导入 App
```

每一关都有硬门槛，**任何一关不过就停下来修，绝不带病交付**：

| 关卡 | 检查什么 | 拦住了什么 |
|---|---|---|
| ① 格式校验 | 字段/枚举/类型是否符合 2.56.1 契约 | 安卓阅读的旧字段混入、非法枚举值 |
| ② 编辑器兼容 | weight 类型、requestFilters 形态等 | 导入能看但**一保存就闪退**的坑 |
| ③ 解析测试 | 保存的真实页面回放解析 | 搜索无结果、字段抓错 |
| ④ 网络四步链 | 搜索→详情→目录→正文真实请求 | 反爬拦截、分页断链、正文空白 |

**特别说明**：② 卡住的是真实事故——早期我们交付的书源能导入、能看书，但**进编辑器点保存直接闪退**。逆向定位到 `weight` 字段类型问题后，这条规则被写死进校验器，之后交付的书源再没犯过这个错。

## 教程：3 分钟看懂这个流程怎么用

### 第一步：告诉 AI 你要哪个网站

把下面这段发给 AI（Codex / ChatGPT 支持 Codex 均可）：

```text
请使用 $xbs-booksource-workflow，并按 skills/xbs-booksource-workflow/SKILL.md 执行。
site=https://www.example.com/
task_type=new_source
keyword=都市
```

### 第二步：AI 自动完成四步

1. **抓样本**：自动抓取该网站搜索/详情/目录/正文四个真实页面
2. **写规则**：根据页面结构生成 JSON 书源规则
3. **四层验证**：格式 → 编辑器兼容 → 页面解析 → 真实网络请求，全部通过才继续
4. **打包**：生成可导入的 `.xbs` 文件，并做「转出-转回」一致性校验

### 第三步：导入香色闺阁

1. 把 `.xbs` 文件发到手机（微信/隔空投送都行）
2. 打开香色闺阁 → 书源管理 → 右上角导入 → 选择文件
3. 确认导入后，搜索试试——能搜到书、能打开详情、目录、正文，就是成功了

> 提示：导入后最好去「书源管理 → 编辑 → 保存」一次（不改任何内容直接保存），确认不会闪退——这是我们四层验证里第②关对应的最终人工确认。

## 我们踩过的坑，都变成了规则

- 搜索被网站关闭？自动降级为分类浏览（九五小说/稷下书院）
- 网站反爬只给首页？直接判定「不可交付」，绝不硬凑
- 繁体/GBK 编码乱码？内置编码解码支持
- 一章分好几页？同章分页自动拼接
- 保存闪退？字段类型硬校验

**这些规则沉淀在一个持续更新的 Skill 里**，AI 每踩一个坑，规则就升级一次——所以我们的书源「越写越稳」。
